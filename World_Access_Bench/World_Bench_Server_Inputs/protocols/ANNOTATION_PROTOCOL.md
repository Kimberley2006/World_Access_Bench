# 自动标注与验收协议

每个实际结果按任务的requirements、preservation_checks、rule_checks、auxiliary_checks逐条判断；原任务gold_status为空表示原来没有结果标签，不能据此推导失败。

## 证据与状态

- pass：适用且证据充分，满足条件。
- fail：适用且证据充分，存在违反条件的观察。
- uncertain：确实检查后仍无法判断，须记录遮挡、采样、关联对象、几何、测量或分歧原因。
- not_applicable：有证据表明规则前提不存在，须写明前提。
- null/not_assessed：未检查；最终必需条件不得停留于此状态。

每条记录包括condition_id、object_ids、applicable、evidence_sufficient、condition_status、evidence_intervals_seconds、observation、reason、measurement、事件存在性和事件区间、标注模型版本、提示版本和视频实际采样记录。不要编造置信概率；只有经定义/校准的输出才能作为概率。

## 时间与连续事件

以结果第一呈现帧为零。事件保留最后明确未发生至首次明确发生的区间，不能把单次抽帧猜测写成精确时间。延迟任务比较源事件[s0,s1]与结果[o0,o1]，延迟区间为[o0-s1,o1-s0]。整个区间落在目标容差内才能通过，完全分离才判失败，交界不确定保留uncertain。

当前0.08秒及相关角度/位置阈值是预先规定的任务设计阈值，未宣称经验校准。不能通过测试表现修改阈值。时长和时间戳变化不直接等于物理违规。

## 物理规则

先确定实际输出的规则适用前提，再判断是否违反。二维重叠不是三维接触；投影位置不是三维稳定性证明；碰撞不存在时不能强行判碰撞响应通过。授权的悬浮仅在指定对象、规则、事件和窗口中生效，超出授权范围仍需判断。

源视频的物理标签、仿真元数据和事件标签只描述源片；编辑后状态必须重新核查。无法获取结果对应的仿真状态时，不假装拥有3D真值。

## 全片断言

“整段从不接触”“一直删除”等断言必须有整个输出时间范围的覆盖审计，记录观察、遮挡、出画和无法排除区间。抽取几张图只能支持局部结论；任何不能排除接触的区间都会阻止全片通过。

## 独立性与复查

两套AI流程先分别输出，保存原始结果，再比较状态、对象绑定、时间区间和理由。相同模型的两次调用必须如实记录为同模型复标，不能冒充不同模型独立证据。优先结合真正不同的标注模型及可验证测量。

两者一致也须审查证据是否支持结论。分歧复查时加载原视频与结果视频的相应片段及必要上下文；最终未解分歧保留uncertain。标注来源一律写AI/程序，human_gold=false。

## 训练掩码

可判定pass/fail用于相应二分类监督；uncertain/not_applicable不映射为负例。适用性与无法判断可以另作监督目标。事件不存在或边界不可确定时，屏蔽相应时间回归损失，不能把缺失值填0秒。未检查的null不能作为任何已经核实的参考。

诊断目录中的旧局部程序标签不自动适用于新任务版本，不能混入正式参考。输出整体严格失败可由一个有充分证据的必需条件失败成立，但不表示其他条件已经全部标注。
